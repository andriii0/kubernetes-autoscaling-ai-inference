Successful latency percentiles use linear interpolation at (n-1)*p; errors are excluded from latency but counted separately. Failure counts are part of completed requests. Dropped iterations never started. started_per_second divides starts by scheduled_seconds (the scheduled load duration). completed_per_second divides completions by client_window_seconds (scheduled load plus any client drain). These rates use different windows and are not a direct completion ratio. Resource summaries use source timestamps within the scenario-start to client-drain interval; idle/warmup and post-load samples remain visible in plots. CPU mean is the arithmetic mean of available source-interval averages, not integrated CPU consumption. Missing rates remain gaps, and CSV missing values are empty. Counts are ten-second buckets; the last bucket can be partial. Whole-run p95 is shown with its sample count. Collection failures remain explicit in the summary; those runs do not establish capacity. For three copies, plots and per-replica-resources.json use each pod's own source timestamps. Total instantaneous resource values stay missing when source timestamps differ; asynchronous rates are not added. For main runs, assessments.json applies protocol targets to the primary start-time phase; primary-resources.json integrates source counter intervals over scheduled load only, with coverage. Node consumption and observed per-instance memory peaks are reported separately.
